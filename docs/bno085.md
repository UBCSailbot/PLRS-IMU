# IMU wiring (BNO085)

The BNO085 (Adafruit 9-DOF breakout) stands in for the MTi-3 on the same
sensor-fusion path. It runs its own on-chip fusion and reports a mag-referenced
Rotation Vector quaternion plus calibrated accel/gyro/mag, which is exactly the
`fusion::ImuSample` the filter already consumes, so nothing downstream changes.
It talks I2C (SHTP + SH-2); the driver lives in `lib/bno08x_imu/`.

## I2C wiring

Four wires. The Adafruit breakout defaults to I2C (no mode jumpers) and carries
its own SDA/SCL pull-ups, so the bus needs no extra resistors, just power the
board.

Both the bench Feather and the boat PCB use I2C0 (`Wire`) on GP16/GP17, the
former MTi UART pads. The Feather's own labelled SDA/SCL (GP2/GP3) are avoided
because GP3 is the rudder output TX.

| BNO085 pin | Signal | Connect to |
|---|---|---|
| VIN | power | 3.3V (accepts 3-6V; the board regulates and level-shifts) |
| GND | ground | GND |
| SDA | I2C data | GP16 |
| SCL | I2C clock | GP17 |

Pins and address live in `src/hardware_config.h` (`BNO_I2C_*`). Default address
is `0x4A` (`0x4B` if the breakout's ADR jumper is bridged).

No INT or RST line is wired: the driver polls for cargos and resets the sensor
in software over SHTP, so the four-wire connection above is the whole harness.

## Debug probe (flashing + telemetry on one cable)

Flashing goes over the CMSIS-DAP/SWD side of the probe (SWCLK, SWDIO, GND into
the target's SWD pads). Upload with `pio run -e feather_rp2350 -t upload`
(bench) or `-e pico2` (boat probe).

Telemetry reads back over the same probe's UART bridge, so the bench needs no
second USB cable. Firmware sends telemetry on UART0 (GP0 TX) as well as the USB
CDC (see `telemetry.h`); wire the target's GP0 to the probe's UART RX (share
GND). The bridge appears as a `/dev/ttyACM` at 115200; `cat` it to see the
`F`/`I`/`M` lines. On the boat the USB CDC carries the same telemetry.

## Bring-up check

The IMU task software-resets the sensor, enables Rotation Vector, accelerometer,
gyroscope, and magnetometer at 100 Hz, then streams. After flashing, watch the
telemetry (`cat /dev/ttyACM0`): the `I` line's quaternion should settle within a
few seconds and track board rotation, and the `M` line should show accel near
1 g on the up axis and a non-zero magnetic field. A steady `# IMU: no reports,
retrying` means the sensor is not answering, so recheck power, SDA/SCL, and the
address jumper.
